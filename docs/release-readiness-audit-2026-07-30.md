# LinkZip 출시 준비 점검 보고서

- 점검일: 2026-07-30
- 범위: 공개 프로필, 관리자, 로그인, 주문·결제, 개인정보, 모바일·아이패드, 접근성, 성능, SEO, Firebase 배포 설정
- 실행 환경: 로컬 Vite 앱, iPhone급 390×844, iPad급 820×1180, 데스크톱, 운영 도메인 응답/헤더

## 결론

현재 상태는 **제한된 비공개 베타 운영은 가능하지만, 불특정 다수를 대상으로 한 정식 출시는 아직 보류 권장**이다. 코드에서 바로 차단할 수 있는 개인정보 노출 및 계정 삭제 문제는 수정했다. 다만 노출된 Meta 비밀키 교체, 통신판매업 신고 정보 확정, 실제 결제·환불 및 소셜 로그인 운영 검증은 외부 콘솔과 실제 계정이 필요한 출시 차단 항목이다.

## 치명적

### 1. 주문 조회가 휴대폰 번호만으로 가능했던 문제 — 수정 완료, 배포 필요

- 재현: 공개 판매 모달의 주문 조회에서 휴대폰 번호만 입력하면 해당 판매자의 주문 목록과 결제된 디지털 상품 다운로드 주소를 받을 수 있었다.
- 원인: 서버가 `ownerUid + buyerContact`만으로 주문을 검색했다.
- 조치: 주문번호와 휴대폰 번호를 모두 정확히 일치시키고 결과를 단일 주문으로 제한했다. IP 해시 기준 시간당 10회 제한과 `no-store` 응답도 추가했다.
- 확인: 프런트·Functions 빌드 및 전체 자동 테스트 통과.

### 2. 회원 탈퇴 중 일부 데이터만 지워질 수 있었던 문제 — 수정 완료, 배포 필요

- 재현: 탈퇴 중 네트워크 오류나 Auth 삭제 실패가 발생하면 사용자 문서 일부만 삭제되고 로그인 계정·하위 문서·파일이 남을 수 있었다.
- 원인: 브라우저가 여러 Firestore 문서를 순서대로 삭제한 뒤 Auth 계정을 삭제했다.
- 조치: 최근 로그인 여부를 확인하는 서버 함수로 통합했다. 사용자·공개 프로필·사용자명·OAuth 연결·Instagram 연결·분석·고객 데이터·오류 제보·방명록 및 관련 비밀정보·Storage 파일을 정리한 뒤 Auth 사용자를 마지막에 삭제한다. Firestore 직접 사용자 삭제는 금지했다.
- 잔여 정책: 법정 보관이 필요한 결제·거래 기록은 개인정보처리방침과 내부 파기 정책에 맞춰 별도 보존·익명화해야 한다.

### 3. 대화에 노출된 Meta App Secret — 외부 조치 필요

- 재현: 이전 작업 중 App Secret 값이 대화에 평문으로 공유되었다.
- 원인: 비밀값을 채팅에 붙여 넣었다.
- 조치 필요: Meta 개발자 콘솔에서 즉시 비밀키를 재설정하고 Firebase Secret Manager의 값을 새 키로 교체한 뒤 관련 Functions를 재배포한다. 이전 키는 폐기한다. 앞으로 비밀값은 채팅·소스·스크린샷에 공유하지 않는다.

### 4. 전자상거래 사업자 고지 미완료 — 외부 조치 필요

- 재현: 푸터의 통신판매업 신고 번호가 `신고 준비 중`으로 표시된다.
- 원인: 실제 신고 번호가 아직 설정되지 않았다.
- 조치 필요: 정식 판매 시작 전 신고/면제 여부를 확인하고 실제 번호, 사업장 주소, 고객센터 정보, 환불 정책을 법률 검토 후 확정한다.

## 출시 전 수정 권장

### 로그인

- Google·카카오·네이버 각각 신규 가입, 기존 로그인, 사용자 취소, 동의 거부, 중복 이메일, 탈퇴 후 재가입을 운영 리디렉션 URI로 검증해야 한다.
- 현재 OAuth `state`와 제한된 복귀 URL 처리는 적용되어 있으나 실제 공급자 콘솔·심사 상태까지 자동 검증할 수는 없다.
- 비공개 베타 초대코드가 없는 신규 계정이 Auth와 Firestore에 잔존하지 않는지 운영 계정으로 확인해야 한다.

### 결제·환불

- 현재 플랜 결제는 자동 갱신 구독이 아니라 월간/연간 **기간제 1회 결제**이며 화면과 약관도 그렇게 고지한다. 자동 갱신으로 판매하려면 Toss Billing Key, 정기 결제 스케줄러, 실패 재시도, 해지·다음 결제일·카드 변경 기능을 별도로 구현해야 한다.
- 실제 소액 결제로 성공, 중복 콜백, 결제 성공 후 브라우저 종료, 금액 변조, 결제 취소/부분 환불, 계좌이체 만료를 검증해야 한다.
- Toss 웹훅 또는 정기 대사 작업을 추가해 관리자 DB와 PG 상태 불일치를 복구할 수 있어야 한다.

### 개인정보·보안

- 개인정보처리방침을 실제 수집 항목, 보유 기간, 외부 로그인, Firebase/Toss/Meta 등 처리위탁·국외 이전, 정보주체 권리 내용으로 확장했다. 출시 전 법률 검토와 정확한 이전 국가/연락처 확정이 필요하다.
- 전역 보안 헤더를 추가했지만 CSP는 Firebase, Toss, Meta, GIPHY 등 실제 허용 도메인을 확정한 뒤 Report-Only부터 도입해야 한다.
- 공개 분석 증가 API와 방명록/익명 제보에는 App Check, 속도 제한, 스팸 방어를 추가 권장한다.
- npm 운영 의존성 점검에서 프런트 High 2건(React Router의 RSC 관련 권고), Functions High 5건·Moderate 7건(주로 Google/Firebase 전이 의존성)이 확인됐다. 이 SPA는 RSC를 사용하지 않아 프런트의 직접 위험은 낮지만, 공식 상위 패키지 수정 버전이 나오면 업그레이드하고 회귀 테스트해야 한다. 자동 `npm audit fix --force`로 Firebase 패키지를 구버전으로 내리면 안 된다.

### 접근성·예외 처리

- 공개 페이지의 공유, 이메일, 달력, 링크 공유, 법적 고지 터치 영역을 44px 이상으로 조정했다.
- 링크 안에 공유 버튼이 중첩되던 잘못된 HTML 구조와 관리자 프로필 카드의 중첩 상호작용을 분리했다.
- 처리하지 못한 React 렌더 오류에서 빈 화면 대신 복구 화면을 제공하도록 전역 오류 경계를 추가했다.
- 출시 전 키보드 탭 순서, 포커스 트랩, 스크린리더 이름, 색 대비를 axe/Lighthouse로 한 번 더 자동 검사해야 한다.

### SEO·배포

- `lang=ko`, 기본 설명, Open Graph, Twitter, canonical, `robots.txt`, `sitemap.xml`, 캐시 및 보안 헤더를 추가했다.
- 공개 프로필은 데이터 로드 후 제목·설명·OG·canonical을 사용자별로 갱신한다.
- SPA HTML 자체는 여전히 공통 메타를 반환하므로 카카오톡/네이버 공유 미리보기와 검색 품질을 위해 공개 프로필 SSR 또는 정적 프리렌더링이 권장된다.
- `www.linkzip.kr`를 `linkzip.kr`로 301 통일해 중복 색인을 막아야 한다.

### 성능

- 공개 프로필은 로그인·관리자 초기화를 건너뛰어 모바일에서 불필요한 Firestore/Auth 경쟁을 제거했다.
- 신규 프로필 이미지는 작은 파일이라도 해상도를 검사해 최대 640px WebP로 저장한다. 기존 2048px 프로필 이미지는 다시 저장하거나 일괄 변환해야 한다.
- Firebase 청크가 약 594KB, 링크 편집기가 약 191KB다. 관리자 전용 Firebase/Auth 모듈의 추가 코드 분할과 긴 목록 가상화를 권장한다.

## 출시 후 개선 가능

- 공개 프로필 SSR/프리렌더와 공유 이미지 자동 생성
- Sentry 또는 Firebase Crashlytics 기반 오류 수집, 개인정보 마스킹, 릴리스 버전 태깅
- Core Web Vitals 및 실제 사용자 성능 모니터링
- Playwright 기반 핵심 E2E: 로그인, 프로필 생성·저장, 상품 주문, 결제 성공/실패, 탈퇴
- 이미지 CDN 리사이징, AVIF `srcset`, 업로드 진행률·취소
- 다국어 법적 문서와 접근성 정기 회귀 검사

## 직접 테스트 결과

- 공개 `/grain`: 데스크톱·390px·820px에서 가로 넘침 없음, 프로필/링크/달력/푸터 렌더 정상.
- 공개 프로필 메타: 제목 `싸리 | LinkZip`, 설명, canonical, OG가 데이터 로드 후 정상 갱신.
- 개인정보처리방침: 확장된 수집·보유·위탁·권리 항목 렌더 확인.
- 프런트: production build 성공, 자동 테스트 32/32 통과, `git diff --check` 통과.
- Functions: TypeScript build 성공, 자동 테스트 16/16 통과.
- lint: 오류 0, 기존 미사용 코드와 Hook 의존성 경고는 남아 있다.
- 운영 도메인: HTTPS와 HSTS는 정상. 새 robots/sitemap/보안 헤더는 아직 로컬 변경이므로 배포 후 재확인 필요.
